- alternatives: (1) 세션 기반 인증(express-session) — 서버 상태 의존으로 Vercel 서버리스 환경과 호환 불가, 기각. (2) NextAuth.js — 당시 App Router 지원이 불안정했고, 블록체인 백엔드와의 커스텀 인증 플로우(API Routes 프록시)를 유연하게 구현하기 어려워 기각.

- implementation: Next.js 미들웨어에서 매 요청마다 JWT 만료 시간을 확인하고, 임계값 이내이면 리프레시 토큰으로 자동 갱신. API Routes에서 백엔드 Hyperledger Fabric 연동 서버로 요청을 프록시하며 토큰을 전달. 역할별(학생/위원/관리자) 라우트 가드를 미들웨어 레벨에서 적용하여, 접근 권한이 없는 페이지 진입 시 리다이렉트.
- outcome: 15개 이상 페이지와 30개 이상 재사용 컴포넌트를 구현하여 Vercel에 배포 완료. 4인 팀에서 프론트엔드 100%를 담당하며, JWT 자동 갱신으로 세션 끊김 없는 3역할 기반 인증 시스템을 구축.
