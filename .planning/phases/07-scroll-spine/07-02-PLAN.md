**Step 1: Create `src/components/lab2/scene/CameraRig.tsx`**

`'use client'` directive. Default export `CameraRig` component that renders `null` (pure logic component, no JSX elements).

Implementation:
1. Import: `useFrame`, `useThree` from `@react-three/fiber`; `useRef` from `react`; `* as THREE` from `three`; `useScrollProgress` from hooks; `CHAPTERS`, `getChapterIndex`, `CHAPTER_COUNT` from config
2. Get camera: `const { camera } = useThree()`
3. Get scroll progress: `const progressRef = useScrollProgress()`
4. Create refs for interpolation targets (initialized once, reused every frame):
   - `targetPos = useRef(new THREE.Vector3())`
   - `targetLookAt = useRef(new THREE.Vector3())`
   - `currentLookAt = useRef(new THREE.Vector3(0, 0, 0))`
5. Define `LERP_FACTOR = 0.05` as a module-level constant (not in component — avoids recreation)

In `useFrame`:
```typescript
const progress = progressRef.current;
const idx = getChapterIndex(progress);
const nextIdx = Math.min(idx + 1, CHAPTER_COUNT - 1);

// Local t within current chapter (0-1)
const chapterStart = idx / CHAPTER_COUNT;
const t = Math.min((progress - chapterStart) * CHAPTER_COUNT, 1);

// Compute interpolated targets between current and next waypoint
targetPos.current.lerpVectors(CHAPTERS[idx].position, CHAPTERS[nextIdx].position, t);
targetLookAt.current.lerpVectors(CHAPTERS[idx].lookAt, CHAPTERS[nextIdx].lookAt, t);

// Smooth camera toward targets (gentle lag on top of Lenis smoothing)
camera.position.lerp(targetPos.current, LERP_FACTOR);
currentLookAt.current.lerp(targetLookAt.current, LERP_FACTOR);
camera.lookAt(currentLookAt.current);
```

**CRITICAL details:**
- LERP both position AND lookAt separately — calling `camera.lookAt()` with un-lerped target causes snapping (research pitfall 5)
- `LERP_FACTOR = 0.05` adds gentle camera lag. Lenis already smooths scroll → combined effect is cinematic. Range 0.03-0.08 is the sweet spot.
- `currentLookAt` ref starts at (0,0,0) matching the first chapter's lookAt — avoids initial snap
- When `idx === nextIdx` (at last chapter), `t` doesn't matter — lerpVectors between same vectors = same vector
- No `camera.updateProjectionMatrix()` needed — only position/lookAt change, not fov/aspect/near/far
